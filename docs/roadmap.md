# 后续执行计划

首版已建立明确范围→历史唤醒→时点快照→决策→账户→回放→有界skill修改的闭环。
仍然是单模块seed-relative搜索；把改进器自身也作为可进化对象，需要另外证明。

1. **先验收A股数据。** 接入一个可追溯来源，保存实际源响应/版本/许可说明，
   独立交易所日历、原价/公司行动、历史证券身份、停牌/价格边界。选择ST切换、
   除权、长期停牌、修订财报和退市案例，建立复杂真实案例回归。未验收字段不开放因子。
2. **冻结一个真实投资实验。** 明确经济假设、策略家族、收益兑现期限和反证；
   冻结开发/验证/封存清单及持有期purge/embargo、费用模型和搜索预算。先做无agent
   基线，再比较等预算随机/网格、真实反馈LLM与打乱反馈LLM，记录成本和失败。
   用预先登记的跨时期迁移和不确定性评估决定是否值得保留。
3. **扩展模块和运行后端。** 对已发现的失败增加因子/skill，不先填满目录。
   proposer/decision接口可接ACP、CC、pi；账户、数据、验收不能被它们修改。
   多skill采用分别校准或策略预算，不能直接合并内部百分位。
4. **再研究严格RSI。** 保存模块父子谱系、冻结对照、合并后全回放、失败回滚；
   让改进器在新任务/新情境的提案效率获得可复验增量。封存评估使用独立进程/权限，
   单独管理重复查询预算。最后才接前向paper观察，仍不自动提交真实订单。

当前唤醒是模拟时间事件，没有创建真实定时任务。未来需要持续paper运行时，再明确
数据到达SLA、真实唤醒时机、断线补数、重启幂等和异常通知策略。
