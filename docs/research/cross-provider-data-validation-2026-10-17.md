# 固定策略数据的跨接口核对

承接 `48f79b5`。本轮不增加策略候选，不更换股票、权重、收益门槛或历史价格。
要回答的是：日频收益所用的原始价格能否得到另一接口支持，以及历史分钟/竞价
来源是否足够完成执行验证。

## 新浪日线捕获协议

- 股票列表完全来自冻结 raw manifest
  `4177efc8615eca4a53fec13161087ca9329b8f1448bc75a41e94179cb368f19a` 的全部 101 个证券。
- 使用新浪公开 `CN_MarketData.getKLineData` 接口，明确传入带沪深前缀的代码、
  `scale=240, ma=no, datalen=1023`。保存原始响应字节、请求参数、收到响应的时间与哈希。
- 只比较原固定窗口 2023-12-29—2026-10-16；窗口外记录计数保留，但不用于核对或决策。
- 空/null、非有限数值、矛盾 OHLC、非整数股成交量、重复或非日频日期均拒绝。
  零成交量也必须满足价格边界，不能用零量绕过校验。
- 网络失败、数据缺失、退市证券接口不可用都记录下来，不能删掉证券或将缺失当零。
- 后续核对从原始响应重新解析，不能仅相信缓存中的 parsed rows。
- 响应不回显证券身份；带代码的请求及价格一致性只能提供交叉证据，不能认证身份。
  抓取时间也不能代替历史真实到达时间。

原始响应保存在本地，仓库只保存代码、来源清单和差异证据。新浪响应和 BaoStock
可能使用共同的上游行情；“跨接口”不表示统计意义上的独立数据源。

## 历史分钟/竞价来源调查

按源码和实际返回核验，不把 README 的“全历史”直接用于回测验收。

- [eltdx](https://github.com/electkismet/eltdx)：核查指定日期历史分时与历史 09:25 正式撮合接口。
  区分实际撮合与虚拟竞价快照；注意历史日期可能是客户端按请求补上的字段。
- [astock-data-toolkit](https://github.com/tiantianlaolao/astock-data-toolkit)：其 15 年回填
  与分钟深度不同；README 单独列出分钟滚动窗口及开盘竞价实时采集限制。
- [通达信官方文档](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1hjbidnohpjn4.html)：
  提供带日期的分笔/分时接口，但 SDK、客户端及实际历史覆盖仍需验证。

只运行有界只读探测，不启动行情网关、后台心跳、定时采集或券商交易。
没有响应、返回近期日期、空结果或分页未完成都不能当作历史数据已取得。

## 取得的数据与核验结果

源核验方法先提交为 `8a42f95`，之后才计算全量订单/撮合记录比值；此前三组
小样本已经查看，已在注册清单中声明。策略、目标和费用回放结果没有改变。

### 日线

101 个证券全部获得有界响应，共 68,003 个活跃证券日的开、高、低、收、成交量
与原始日线精确一致，没有使用容差。原始 68,074 行中包含停牌记录；不能把两种
计数混为缺失行情。当前 15 个有效费用/资金回放涉及的 1,277 个独立成交日开盘、
23,920 个独立持仓日收盘也全部匹配；10 个停牌持仓日沿用估值继续单独标记。

[新浪捕获清单](../../experiments/qlib/sina-daily-crosscheck-manifest.json)与
[精确核对结果](../../experiments/qlib/sina-daily-crosscheck-results.json)保留全部证券。
没有把新价格混入旧回放，也没有根据匹配情况剔除证券。

### 历史分时与开盘撮合

安装并记录 `eltdx 3.2.3`，仅使用读行情接口，关闭后台心跳及主站测速，脚本退出时
关闭连接。新数据保存了原始分钟 payload/记录 hex、请求日期、节点和捕获时间。
检查过的源码提交为 `f6287f69f68354b4b550d132ebec565ee749fa8d`。

冻结回放全部有效场景的精确订单并集为 1,299 个证券日：

- 全部 1,299 个请求均已保存响应，无请求异常；其中 1 个为原来源已知停牌日。
- 1,298 个活跃证券日全部有 240 个明确交易时段标签，尾收盘价都与原日线一致，
  有成交的分时价格也均落在对应日线价格区间内。
- SDK 文档把分钟量与开盘撮合量定义为“手”。按这一单位解释后，1,298 个活跃日的
  分时合计都等于日股数换成手后的最近整数。这个吻合仅作精度诊断；它既不是
  逐股核验，也不允许修改旧 BaoStock 分钟量或放宽其失败检查。
- 取得 1,296 个严格标为 09:25 的实际撮合记录，价格全部与对应日开盘价一致。
  3 个请求未识别到该记录，其中包括已知停牌日；没有将空值转成零成交量。

三组先导样本在两个节点上逐字节一致。节点同属供应商体系，不表示独立上游；
请求日期也可能由 SDK 填入，历史日期并未获得交易所回显认证。

[捕获清单](../../experiments/qlib/tdx-fixed-order-history-manifest.json)、
[先导样本](../../experiments/qlib/tdx-history-probe-manifest.json)及
[完整诊断摘要](../../experiments/qlib/tdx-fixed-order-history-audit-results.json)包含数据哈希与边界。
全量逐日诊断保存在本地，其哈希写入摘要，原始 vendor 文件不随仓库分发。

### 分页修复与已有数据保留

审查发现，SDK 的 4 页上限可能抛 `RuntimeError`，不能仅在返回 `None` 时补扫。
V2 已加入只针对该分页异常的 4→16 页有界补扫、其他异常保留及最终上限退出测试。
V2 默认另存目录，原 V1 源码逐字节归档并与已捕获 manifest 的源码哈希核对。

这次 V1 的 1,299 个分钟请求和 1,299 个撮合请求中均没有请求异常，因此无受该
缺陷影响的待补采记录；原始响应未被覆写。3 个未匹配结果已经做过 16 页扫描。

### 对原订单规模意味着什么

以下比较的是**单笔模拟成交数量与已观察的 09:25 撮合记录**。原 broker 的成交
时间戳是 09:30，两者不是同一个时点，不能把这张表当作新的成交仿真。

| 初始资金／额外每边费用 | 大于已观察撮合量10%的成交笔数 | 大于该撮合量的成交笔数 | 最大比值 |
| --- | ---: | ---: | ---: |
| 10 万／0bp | 0 | 0 | 7.55% |
| 100 万／0bp | 42 | 0 | 79.25% |
| 100 万／20bp | 42 | 0 | 79.25% |
| 100 万／40bp | 42 | 0 | 77.36% |
| 1000 万／0bp | 217 | 43 | 813.21% |
| 1000 万／20bp | 218 | 42 | 803.77% |
| 1000 万／40bp | 217 | 42 | 794.34% |

表中为示例档位，全部 15 个有效场景均在 JSON 摘要中；没有选一个档位作为通过。
每个场景还有 1 笔成交缺少严格 09:25 对照，保留未知，不从分母中隐去。

最大比值来自 SH601928/2026-07-01：源记录为 53 手（按文档换算 5,300 股），
100 万/20bp 买入 4,200 股，1000 万/40bp 买入 42,100 股。
另一例 SZ001213 同日为 300 手，1000 万/40bp 卖出 103,100 股。
补取这两日完整成交明细，各自都只有一条正式开盘撮合记录，避免把一条分片
误当成全量。明细仍不能提供增加订单后的反事实队列和价格响应。

**超过已观察撮合量不证明现实中绝对无法成交。** 新增订单可能改变价格和匹配量；
即使低于该量，也不证明能排到对手盘。这里的结论是：原日开盘代理没有解释这些
订单如何无冲击地完成，因而不能据此认证 +10.06% 的大资金结果。

### 两个未知日期

SZ000027、SZ000898 在 2024-10-08 的完整历史明细都从 09:26 的中性成交开始，
价格与各自日开盘一致，没有严格 09:25 的记录。SDK 将它们分类为普通成交。
不能直接说“当天没有开盘竞价”，也不能为了让核验通过把 09:26 改写为 09:25。

补查样本、首条记录、全日笔数和原文件哈希见
[成交上下文探测](../../experiments/qlib/tdx-opening-context-probe-manifest.json)。
这些未知与时间戳解释继续留在验收缺口中。

## 当前结论与下一步

日线价格获得了全目标范围的交叉支持，也找到了可按日期取得的历史分时/撮合来源。
旧 900 个 BaoStock 分钟量差异并未被“修好”，而是作为不采用该数据做执行证明的
理由原样保留；新来源也保留手数精度、日期回显及队列未知标签。

当前收益仍是日开盘代理模型的结果。后续若建立盘中成交模型，必须先只用
2024—2025 年数据及通用执行约束定义和冻结，再运行 2026，不能利用本轮看到的
股票、日期和薄量成交来定制策略。完整十月、用户资金量、真实到达时间和市场
冲击仍未验证，目标保持未完成。
